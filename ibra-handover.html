IBRA Address Book — Ownership Handover Guide

What needs to move to the new owner, and in what order, so syncing never breaks.

1. How the pieces fit together

Four things make this app work, each owned/controlled separately in Google's systems:

Data flow: Sheet edit → Apps Script trigger → Firebase → website reads from Firebase (with a local offline copy cached on each visitor's device).

⚠ Read this before transferring anything The Apps Script triggers that watch the Sheet for edits run under the identity of whoever clicked "Run" when they were installed — not whoever currently "owns" the Sheet or script file. Transferring ownership of the Sheet or script does not automatically move the triggers to the new owner. If the old owner's access is removed before the new owner re-installs the triggers themselves (step 3 below), syncing will silently stop. Follow the order in this guide to avoid any downtime.

2. Transfer the Google Sheet

  1. Open the Sheet → Share button (top right).
  2. Add the new owner's Google account if not already a collaborator, with Editor access.
  3. Next to their name, open the role dropdown and choose Transfer ownership (or "Make owner", depending on your Drive version). They'll get an email to accept.
  4. Do not remove your own access yet — keep yourself as at least an Editor until step 3 is fully confirmed working.

3. Transfer the Apps Script project

A standalone Apps Script project is also a Drive file, so the same sharing mechanism applies:

  1. Open the script project at script.google.com → the three-dot menu or Share icon → add the new owner with Editor access, then transfer ownership the same way as the Sheet.
  2. Have the new owner personally do this next part (it must run under their own login, that's the whole point): open the script, select installIbraSyncTriggers from the function dropdown, click Run, and approve the authorization prompt under their own Google account.
    This function already deletes any existing triggers for the same two handler functions before creating new ones, so it's safe to run again — it replaces the old owner's triggers with the new owner's, with no risk of duplicates.
  3. Confirm it worked: in the Apps Script editor, left sidebar → Executions — make an edit to any row in the Sheet and confirm a fresh handleEditTrigger entry appears, owned by the new account.
  4. Only now is it safe to remove the old owner's access from both the Sheet and the script project, if desired.
✓ Good news: Script Properties travel with the project automatically The three Firebase credentials (FIREBASE_DB_URL, FIREBASE_CLIENT_EMAIL, FIREBASE_PRIVATE_KEY) are stored on the script project itself, not tied to a particular person. Whoever has edit access to the script can see/use them — nothing to re-enter here during a script ownership transfer.

4. Hand over the Firebase project

Firebase/Google Cloud projects don't have a single "transfer ownership" button the way Drive files do — instead you add the new person as an Owner, then optionally remove yourself once they've confirmed access.

  1. Firebase Console → open project ibra → Project settings (gear icon) → Users and permissions tab.
  2. Click Add member, enter the new owner's email, set role to Owner.
  3. Ask them to confirm they can see the project at console.firebase.google.com.
  4. Once confirmed, you can remove your own account from the project's permissions if you no longer need access (optional — many people just leave both as Owners).

What about the service account key already in use?

The existing service account (firebase-adminsdk-fbsvc@ibra-baf92.iam.gserviceaccount.com) is a machine identity — it keeps working regardless of which human is "Owner" of the project. You have two reasonable options:

  • Simplest: change nothing. The existing key keeps the sync working under the new ownership with no further action.
  • Cleaner for a full handover: have the new owner generate a fresh service account key under their own control (Project settings → Service accounts → Generate new private key), update the three Script Properties in the Apps Script project with the new values, then delete the old key (Google Cloud Console → IAM & Admin → Service Accounts → find the account → Keys tab → delete the old one).
⚠ Never put a private key in an email, chat, or document like this one If you do pass along the existing key file, share it through a secure channel only (password manager, encrypted file transfer) — never as plain email text or pasted into a doc.

5. Verify everything after handover

  • New owner can open the Sheet and the Apps Script project directly (not just via a link you sent).
  • An edit made to a row in All Addresses shows up in Firebase Console → Realtime Database → ibra/addbook within a few seconds.
  • Apps Script → Executions log shows the trigger running under the new owner's account, with no errors.
  • The live website still loads and shows current data.
